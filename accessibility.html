Accessibility Statement

Last Updated: January 15, 2025

DataCaboose is committed to ensuring digital accessibility for all users, including people with disabilities. We strive to provide an inclusive experience that enables everyone to access our Canadian cloud services effectively and efficiently.

♿ Accessibility First: We believe technology should be accessible to everyone. Our commitment goes beyond compliance to create truly inclusive digital experiences.

1. Our Accessibility Commitment

1.1 Our Promise

DataCaboose is dedicated to:

  • Providing equal access to information and functionality
  • Meeting or exceeding Web Content Accessibility Guidelines (WCAG) 2.1 Level AA standards
  • Complying with the Accessible Canada Act and provincial accessibility legislation
  • Continuously improving our digital accessibility
  • Training our team on accessibility best practices

1.2 Accessibility Standards

Our digital properties conform to the following standards:

  • WCAG 2.1 Level AA: Web Content Accessibility Guidelines
  • Section 508: U.S. federal accessibility standards
  • EN 301 549: European accessibility standard
  • AODA: Accessibility for Ontarians with Disabilities Act
  • Accessible Canada Act: Federal accessibility legislation

2. WCAG 2.1 Compliance Status

WCAG Principle Guidelines Conformance Level Implementation Status
Perceivable Information must be presentable in ways users can perceive AA Fully Implemented
Operable User interface components must be operable AA Fully Implemented
Understandable Information and UI operation must be understandable AA Fully Implemented
Robust Content must be robust enough for various assistive technologies AA Fully Implemented

3. Accessibility Features

Visual Accessibility

  • High contrast color schemes
  • Scalable text and UI elements
  • Alternative text for images
  • Clear visual hierarchy
  • Support for zoom up to 200%

Keyboard Navigation

  • Full keyboard accessibility
  • Visible focus indicators
  • Logical tab order
  • Skip navigation links
  • Keyboard shortcuts

Screen Reader Support

  • Semantic HTML markup
  • ARIA labels and descriptions
  • Proper heading structure
  • Screen reader announcements
  • Compatible with NVDA, JAWS, VoiceOver

Mobile Accessibility

  • Touch-friendly interface
  • Minimum 44px touch targets
  • Gesture alternatives
  • Portrait and landscape support
  • Voice control compatibility

4. DataCaboose Platform Accessibility

Customer Portal Features

  • Fully keyboard navigable dashboard
  • High contrast mode toggle
  • Text size adjustment controls
  • Screen reader optimized forms
  • Alternative text for all graphics and charts
  • Consistent navigation structure
  • Error messages with clear instructions

Management Console Accessibility

  • ARIA-compliant interface components

5. Assistive Technology Support

5.1 Screen Readers

DataCaboose is tested and optimized for:

  • NVDA (Windows): Full compatibility with latest version
  • JAWS (Windows): Comprehensive support for all features
  • VoiceOver (macOS/iOS): Native support for Apple devices
  • TalkBack (Android): Mobile accessibility support
  • Orca (Linux): Open-source screen reader compatibility

5.2 Voice Control Software

  • Dragon NaturallySpeaking: Voice navigation and control
  • Windows Speech Recognition: Built-in Windows accessibility
  • Voice Control (macOS): Apple's voice navigation system
  • Voice Access (Android): Google's voice control solution

5.3 Alternative Input Devices

  • Switch navigation devices
  • Eye-tracking systems
  • Head-mouse devices
  • Specialized keyboards
  • Joystick and gamepad controllers

6. Canadian Accessibility Legislation Compliance

6.1 Accessible Canada Act

DataCaboose complies with the Accessible Canada Act by:

  • Publishing this accessibility statement
  • Maintaining an accessibility plan
  • Providing multiple ways to receive feedback
  • Training employees on accessibility
  • Implementing accessibility policies and procedures
  • Regular accessibility audits and assessments

6.2 Provincial Accessibility Laws

Accessibility for Ontarians with Disabilities Act (AODA):

  • WCAG 2.0 Level AA compliance for web content
  • Accessible customer service standards
  • Workplace accessibility policies
  • Procurement accessibility considerations

Accessibility Standards Canada (ASC):

  • Following emerging federal accessibility standards
  • Participating in accessibility standard development
  • Implementing best practices for digital accessibility

7. Testing and Quality Assurance

7.1 Regular Testing Methods

  • Automated Testing: axe-core, Pa11y, and Lighthouse accessibility audits
  • Manual Testing: Keyboard navigation, screen reader testing, color contrast verification
  • User Testing: Testing with actual users who have disabilities
  • Third-Party Audits: Annual accessibility assessments by certified experts

7.2 Accessibility Testing Tools

Our Testing Toolkit

  • axe DevTools: Automated accessibility testing
  • WAVE: Web accessibility evaluation tool
  • Colour Contrast Analyser: Color contrast validation
  • Accessibility Insights: Microsoft's accessibility testing tool
  • Pa11y Command Line: Automated accessibility testing for CI/CD

8. Known Issues and Limitations

8.1 Current Limitations

We are actively working to address the following known issues:

  • Legacy Systems Integration: Some older third-party integrations may have limited accessibility features
  • Complex Data Visualizations: Some advanced charts may require additional navigation methods
  • PDF Documents: Working to ensure all downloadable PDFs meet accessibility standards

8.2 Workarounds and Alternatives

  • Alternative data formats available upon request
  • Phone and email support for complex tasks
  • Screen reader compatible alternative views for charts
  • Accessible PDF versions of all documentation
